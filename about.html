About this demo

Seeing what the platform is doing

Every page carries an on-page SDK console — the pill in the bottom right. Open it to watch each payload as it leaves the browser: page type, user attributes, basket, custom events. It also logs notes from the site itself, so campaigns, affinity and the agent all announce themselves there.

  • ?debug=0 hides it, for a clean screen share.
  • Notes are colour coded — green for confirmations, amber for warnings.

Install the Insider One Chrome Extension. It is needed for Action Builder to work properly when you build campaigns against these sites, and it makes event inspection considerably easier.

Things worth trying

  • The line under the search box is a dare. Take it — the payoff is the point.
  • ?affinity=1 turns on the affinity exhibit. It ranks what you see by what you have browsed, and shows a panel explaining itself. Turn it off from that panel, or with ?affinity=0.
  • Book something from the services link in the header. It writes a durable attribute to your profile, which you can then see in the panel.
  • Buy something. Revenue and line items land on the profile a minute or two later.

What is real and what is not

Everything the platform does is labelled. Recommendation rows name the algorithm and the campaign id above the grid, so you can open the campaign and check. Anything computed by the site rather than the platform says so — the affinity exhibit is the main one, and it is marked site-side wherever it appears.

If a block does not say where it came from, it came from the catalogue.

Known gaps

  • Some recommendation slots return nothing. Those are waiting on account configuration rather than being broken.
  • Predictive segments and affinities need around thirty days of history, so they read as Not Available on fresh profiles. That is expected.
  • Search matches product names well and descriptions less well, pending a searchable-attributes change.
